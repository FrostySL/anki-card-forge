# v2.0.0 — Native Windows setup and provider-independent workflows

Anki Card Forge now runs directly on Windows 11 x64 and works with an AI
assistant of your choice. This release also strengthens learned-deck reworking,
backup recovery, and the checks that run before publishing project changes.

## What's new

- **Native Windows setup:** `forge.cmd setup` installs a managed local
  toolchain with normal user permissions. No preinstalled Python, Git, Docker,
  or WSL is required. ZIP downloads work too. Tools and caches stay in `.forge/`
  and Python packages in `.venv/`.
- **Offline processing after setup:** local sources, OCR, card building,
  validation, and formula previews work without internet. Previews use local
  MathJax, including dynamically loaded extensions. English and German OCR are
  included; setup can add other languages. The chosen AI assistant has its own
  connectivity and data-handling requirements.
- **Provider-independent authoring:** shared instructions now live in
  `AGENTS.md`, `skills/card-authoring/`, and `workflows/`. Claude Code adapters
  remain available. The repository makes no model API calls and requires no
  provider API key.
- **Clearer onboarding:** the README leads through platform setup, adding a
  source, asking the assistant to create cards, and importing the result.
  Linux and WSL2 retain the Docker workflow.

## Reliability improvements

- AnkiConnect backups find affected notes by GUID as well as deck name, so
  renaming a deck does not bypass its backup. `restore` makes a fresh backup,
  restores older content, and verifies the result and existing learning
  progress. Use `restore` for recovery: a plain import can skip older content.
- Package comparisons include every note and raw field, including occlusion
  and foreign note types. Strict comparisons reject incompatible note types,
  field layouts, and card ordinals. Additions and removals still need review.
- Reworking type-in and reversed basic notes preserves their separate `More`
  field. Incomplete CLI decoding now fails before writing card JSON, instead
  of silently omitting unsupported notes.
- Shared JSON validation and image parsing catch invalid field types and
  preserve images in valid HTML. Rotated PDF figures are cropped correctly.
- Windows launchers handle paths and arguments more reliably. Use `forge.ps1`
  directly from PowerShell for literal HTML with embedded quotes or shell
  metacharacters.

## Upgrading and compatibility

Existing card JSON, stable note-type IDs, and note GUIDs remain compatible.
Already learned decks still require a fresh Anki export before reworking;
preserve GUIDs and cloze tokens, then review a strict package diff.

On Windows, update the project and rerun `forge.cmd setup`, then
`forge.cmd doctor`. The release updates the project version in the lockfile,
so an earlier managed setup must refresh its recorded state. With all required
components cached, `forge.cmd setup --offline` can perform that refresh.
Linux/WSL2 users should rerun setup and rebuild the Docker images they use
after updating. See the [setup instructions](https://github.com/FrostySL/anki-card-forge/blob/v2.0.0/README.md#quick-start).

Image-occlusion creation, preview, and validation are supported. Full
export-to-JSON rebuilding of occlusion notes and unsupported field/deck layouts
is not supported: the decoder refuses incomplete conversions. A mirror may
contain a partial JSON index; keep its original `.apkg` as the complete backup.

Restore keeps later-added notes and does not roll back deck placement or
note-type styling. Use Anki's own collection backups for full recovery.
Sync remains an explicit user action. macOS, Windows ARM64, and Docker-free
Linux setup are outside the supported platforms.

## Verification

The automated suite contains 314 tests. Required CI covers Python tests,
repository-file protection, shell and Dockerfile linting, real Anki validation,
and a cold Windows setup with an offline repeat. This release also runs the
PDF/OCR and light/dark preview integration checks.

During development, a clean Windows Sandbox run as a standard user passed
setup and a repeat with its network disabled. A separate live Anki test
verified reworking and recovery while preserving learning progress and review
history. These are documented development checks, separate from release CI;
the [Windows acceptance report](https://github.com/FrostySL/anki-card-forge/blob/v2.0.0/docs/windows-acceptance.md)
records the setup and initial rework evidence.
